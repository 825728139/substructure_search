# reaction 来源的首版可用性审查

检查日期：2026-10-27。范围：用户指定的 PostgreSQL `reaction` 模式，只读查看结构、统计当前 427 条反应、检查结构与模板，并抽查 5 条反应的原文。没有修改来源表、数据或持久化配置。本文件是接入审查，不改写主计划的数据库无关设计。

**结论：现有表足以作为首版结构召回与原文参考的数据源，建议直接接入只读适配器。要可靠判断“是否提供目标连接方法”“能否替换一个底物”和实验适配排序，还需要恢复完整映射、补提条件并做逐项质量核验。无需先重建整套表。**

## 2. 哪些字段可以直接接入

| 字段 / 对象 | 首版用途 | 接入边界 |
|---|---|---|
| `product_smiles`、`products_mol` | 整体、核心、局部结构的产物召回 | `products_mol` 是整侧聚合表示；最终回到具体材料实例确认命中 |
| `reactant_smiles`、`reactants_mol` | 展示源反应底物、来源锚定的反应物补查 | 不能把整侧断开图当作一个完整底物 |
| `reagent_smiles`、`catalyst_smiles`、`solvent_smiles` | 展示条件参与物和基本筛选 | 角色来自抽取结果，不能直接等同于机理角色或原子供体判定 |
| `reaction_smiles` | 源记录展示、粗重复聚类 | 左侧混合反应物与试剂，排除了催化剂、溶剂；不保留材料实例边界和完整映射 |
| `product_fp`、`reactant_fp` | 相似度补充与软排序 | 本库是 radius=2、2048 位 Morgan；不要当作必经的子结构相似度阈值过滤 |
| `reaction_center_r1`…`r4` | 转化模式候选、局部环境比对 | 是 **radius 1–4**，不是 Markush 的 R1–R4；方向为 **产物 → 反应物** |
| `reaction_details` | 名称、原始结构、用量、质量、体积和产率字符串 | 二维数组需按列说明转换为具名对象，保留原值与缺失状态 |
| 来源组合键、`reaction.evidence` | 来源引用、原文展示、条件补提 | `id` 用于本地关联和分页；公开来源依赖文档、段落及段落内序号 |
| `reaction_import_documents` | 来源文件摘要和导入版本追踪 | 可帮助固定导入来源；尚不能代替全部规则、映射和参数的版本记录 |

已经实测 `products_mol @> 'c1nnco1'::qmol` 命中 50 条；执行计划使用 `reactions_products_mol_gist`。普通 SMARTS 召回可直接使用现有能力，不需要先增加另一套基础结构索引。此小样本结果不是大规模性能承诺。

## 3. 接入时必须处理的问题

### 3.1 指纹参数：存储 2048 位，新连接默认 512 位

427 条产物和反应物指纹的长度都是 2048，但本次新连接的 `rdkit.morgan_fp_size=512`，直接调用 `morganbv_fp(...,2)` 生成的也是 512 位。

读取适配器需为相似度查询显式设置一致参数，例如在查询事务内 `SET LOCAL rdkit.morgan_fp_size=2048`，同时固定半径、结构规范化和版本。实测按 radius=2、2048 位重新计算，两侧分别 427/427 与存储指纹逐字节一致。检查结束即恢复会话原设置，没有更改全局配置。

该问题不会让独立的 `products_mol @> qmol` 查询自动失效；它影响的是依赖显式 Morgan 指纹的相似度计算。子结构和相似度是不同查询能力，不能用统一 Tanimoto 门槛替代 Markush 召回。[RDKit cartridge 的操作符与参数说明](https://www.rdkit.org/docs/Cartridge.html#reference-guide)

### 3.2 聚合 mol 不保证所有锚点属于同一个实际分子

数据库实测 `'CO.CN'::mol @> 'O.N'::qmol` 返回 true：两个要求可以分别落在两个不同分子上。这是人工反例，不是来源中的真实反应。

目前所有产物条目都是单个连通结构，因此未在这批产物中观察到多产物拼接的实例。但反应物有 49 个条目本身是断开的盐/多组分表示；更不能根据 `reaction_smiles.split('.')` 恢复材料实例。原数组中一个盐条目可能包含几个图组分，几份同结构材料也可能属于不同投料阶段。

接入后应保留 `来源记录 + 角色 + 条目序号 + 导入版本` 形成的材料实例引用，另维护实例内组分。Markush 联合要求在同一候选材料的指定主体、同一核心映射下核验。数据库固定核心预筛之后，再执行 R 位点、整支链、可选 H、桥接和相对位置检查；不能只靠断开的 SMARTS 或单个 `*` 完成这些语义。RDKit 的部分通用基团匹配还需要显式启用。[RDKit Generic Markush 说明](https://www.rdkit.org/docs/RDKit_Book.html#generic-markush-queries-in-substructure-matching)

### 3.4 完整映射与目标连接贡献仍有缺口

`reaction_center_r1`–`r4` 中的 atom-map 是模板内部对应，不等于可直接定位到 `product_smiles` / `reactant_smiles` 每个实例原子的完整映射。不同半径的模板标签也不能直接当作同一全局原子 ID。

建议首先核对导入所用的 AAM 原始文件是否保留完整映射；导入日志有文件摘要，但本次没有打开这些原文件。若可恢复，接入结果至少携带：完整映射反应、映射方法及版本、各侧材料实例到映射原子的对应、核验状态和失败原因。缺失时仍允许返回结构与原文参考，目标连接贡献标为未知。

随后针对用户目标计算：成键、断键、键级变化发生在哪里；是否跨过目标母核—支链边界；相关片段来自哪个真实底物；属于引入、原有片段保留、其他基团修饰，还是无法确认。**这些目标相关的结论属于检索分析结果，不要求全部提前变成数据库静态字段。**

现有 `reaction_class` 是叶子类别 ID，需配套类别名称、分类体系版本和来源；它可以辅助解释，不能代替上述原子与键变化分析。

## 4. 条件字段可保留，但需要修复抽取并区分阶段

字段设计已有温度、时长、压力范围和单位，这是合理起点。目前问题是数值字段与原始条件字符串都为空，且抽查原文明确存在这些信息：

| reaction id | 原文可核对的信息 | 目前字段状态 |
|---|---|---|
| 1 | 回流 18 h；产率 80% | 时间、温度文本和收率均缺失 |
| 2 | 两个容器分别处理、随后合并继续反应；有气体析出提示，另有后处理降温 | 条件数值和原始字符串均缺失 |
| 3 | 加料前冷却到 0°C，随后 RT 搅拌 16 h；产率 86% | 条件缺失，产率 86% 已保存 |
| 100 | 先 90°C、1.5 h，再加入另一底物后 110°C、5.5 h；随后制备 HPLC | 条件缺失；仅全局范围也不能表达两个阶段 |
| 200 | 先 90°C、1.5 h，再加入另一底物后 110°C 过夜 | 条件缺失；“过夜”不宜强行变成唯一精确时长 |

这些信息足以证明至少存在提取/导入链路的遗漏，但尚未定位到具体哪个上游程序。不能把 RT、回流、过夜、减压等全部当作数值缺失，也不能擅自给出确定温度或压力。原文没有压力数值也不能自动填成常压。

首版先恢复原始条件文本和出处，并给解析状态。以后按阶段关联温度、时长、加料、气氛、后处理和纯化；全局 min/max 留作粗筛摘要。收率要附产物实例、是否分离收率/分析收率及原始表述；当前 `yield_min/max_pct` 是所有产物产率的汇总，多产物出现后不能当作目标产物的收率。

实验适配排序还需要来源中的规模、纯度/分离方式、投料与控制要求、专用装置、操作提示等。分子量和基础官能团可在应用层从结构计算；危险信息、活性与操作难度不能从某个原子、空条件或 `final_score` 单独推出。资料未核实时返回未知，仍可以给出方法参考排序。

## 5. 对现有详情格式和数据范围的意见

二维数组的长度约束与列注释明确，本批检查全部符合约定，首版可以直接适配，暂不要求改表。但产品 8 列、反应物/试剂/催化剂 9 列、溶剂 8 列，必须按角色解析成具名对象，不能统一按同一个位置格式读取。

所有 2255 个详情条目的 `id` 都为空。首版由适配器提供材料实例引用；原本存在重复投料时保留份数及序号，不按 SMILES 去重。例如 id=2 的详情记录了两份同结构 THF，各 2100 mL，不能自动当成重复数据删掉。

从材料角色数组组装 `ReactionRecord`，而非重新从混合反应式推回角色。当前表示可以展示记录，但没有显式表达实验结果状态、主产物/副产物角色、多阶段归属、拆分富集与实际构筑的区别。这些状态可先在适配结果中标未知，再逐步从证据补齐。

导入日志合计原始 906 条、导入 427 条；未核验剩余 479 条各自排除原因。应检查是否有“结构可用但映射不可靠”的记录被一并排除：这类记录可能仍可用于初步分子/原文参考，只需禁止进入确定的连接方法证据。不能把所有未导入记录都认定为应恢复的数据。

资料几乎集中于一篇专利，且存在重复产物和反应式。用它验证适配和典型查询合适；评测召回率、方法多样性或一般排序质量，需要补充不同来源、不同反应族和正反例。评测拆分应考虑文档与近似物系列，避免同一专利的相似条目同时用于调参与验证。

## 6. 建议实施顺序

1. **立即接入**：只读来源适配、现有 GiST 粗召回、具体产物/底物实例与原文返回；显式对齐指纹参数，区分结构命中与方法未知。
2. **并行补数据**：核对并恢复完整 AAM，修复条件原文遗漏，复核 3 条手性模板异常；对解析失败/未知状态做明确标记。
3. **完成方法参考分析**：基于已核验对应做实际键变化、母核—支链贡献和环变化分析；再提供有来源约束的单底物替换建议。
4. **逐步完善排序与覆盖**：补阶段、结果类型、产率口径和来源数量；在证据足够的字段上排序，缺失不评分为容易或安全。
