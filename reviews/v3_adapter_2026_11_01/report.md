## 已实现

- PostgreSQL默认读取 `reaction.reaction_v3`。显式 `RR_POSTGRES_TABLE=reactions` 可使用旧表，不自动回退。
- 初选要求组最高分≥12；随后从 `reaction_v3_source_scores` 选自身分数≥12且为最高分的实际来源，并列按最小来源ID。
- 先选择窄的来源ID，再从 `reaction_v2` 按主键读取该实验的材料、映射、反应中心、条件和定位。组代表的低分映射或条件不再混进分析。
- 在结构匹配前即绑定所选来源的材料及原子顺序。详情通过组ID和来源ID从 `reaction_v3_details` 获取，并再次核对来源定位；错误时不能改用其他实验详情。
- 产物和反应物的完整GiST、同列 `IS NOT NULL` 部分GiST均可识别。任意其他条件的部分索引不被误认为覆盖全部候选。
- 每组当前只评估一条最高分来源，其他成员仍在数据库保留。资料包 `record.raw.dedup_source_selection` 记录组ID、组最高分、实际来源ID/分数、成员数量和未评估其他来源的范围说明。

默认不按温度、压力、产率、设备等反应条件预筛。新增分子量数组和DRFP未在本次额外接入；化学排序算法也未改动。

## 验证与耗时

完整本地检查 **479项通过、无跳过**，包括58项真实PostgreSQL测试。所有测试写入只发生于自动创建并清理的本机私有库；验证运行额外安装连接拦截，拒绝共享库及TCP连接。Ruff、mypy、中文说明、契约检查及wheel构建通过。

真实库重测同样11个目标，每个两次，共22次：10秒预算、40任务、60条反应分析、SQL超时1.5秒，并发1。调用正式 `PostgresSource(table="reaction_v3")`，计时包装不再改写SQL表名。计时包含子进程启动、连接、检索和结果序列化，不是HTTP并发压测。

| 指标 | 本次结果 |
|---|---:|
| 中位耗时 | 3.33秒 |
| P95 | 6.02秒 |
| 最快—最慢 | 1.58—6.66秒 |
| SQL超时 | 1次，T04首轮来源选择 |
| 默认停止原因 | 22次均包含任务预算限制 |
| 首轮前五名明确有用 | 28/55（50.9%） |
| 重复轮前五名明确有用 | 30/55（54.5%） |

两个计时口径不能直接等同：上一轮v3报告中位2.72秒/P95 4.14秒，使用的是更新组最高分之前的代表行模式；本次数据库分数语义、合格来源选择和数据读取范围都变了，缓存和本机负载也未严格控制。增加来源选择确实有开销，但不能把全部差异归因于单一改动。

第一次真实试测发现“组内宽字段排序”会反复超时，已在最终实现中改成先用最高分标记和有序来源ID取一条，再加载完整记录。该初始试测留在本地 `pre_validation/`，不计入最终22次。最终仍有一次1.5秒超时，未从报告中删去；它触发部分结果路径且影响T04排名。

## 化学效果

我逐条核对首轮55个前五名位置，并对结果变化的T04第二轮额外审核5个位置，共60条判断。共涉及57条实际来源，49条找到原文；同目标同来源的既有判断在结构/来源一致时沿用，新增记录重新核对。A/B表示明确局部方法或直接目标参考，C为待补证/弱线索，D不相关，E为矛盾/错误来源。没有实验验证或独立双人盲评，不是全库准确率或合成成功率。

| 目标 | 适配首轮有用@5 | 重复轮有用@5 | 主要观察 |
|---|---:|---:|---|
| T01乙酰苯胺 | 1/5 | 1/5 | 来源缺原文和结构冲突仍占位，最高分选择不能修复这些问题 |
| T02无环氨基酯 | 3/5 | 3/5 | 12分脱保护来源恢复，叠氮还原也有明确关联 |
| T03联芳基 | 5/5 | 5/5 | 仍以Suzuki及有机锌偶联等实际方法为主 |
| T04哌啶苯甲酰胺 | 1/5 | 3/5 | 首轮超时漏掉部分家族，第二轮恢复更多酸胺缩合先例；矛盾苄氯记录仍排第一 |
| T05β酮酯 | 3/5 | 3/5 | Meldrum酸中间体醇解与Claisen方法仍可用 |
| T06手性脯氨酸酯 | 4/5 | 4/5 | 可用保护/酯化方法与错误代号解析并存，立体支持必须独立判断 |
| T07酰化Meldrum酸 | 4/5 | 4/5 | 直接及近似酸端的C酰化方法有效，但仍夹杂噻唑成环噪声 |
| T08内酰胺 | 4/5 | 4/5 | 有还原和内酯氨解线索，背景路线里的前后步骤不能并入同一实验 |
| T09多取代芳酰胺 | 1/5 | 1/5 | 只有一般酸—脂环胺酰化有局部参考，代号误解析和无关转化仍突出 |
| T10联芳基羟乙基酰胺 | 2/5 | 2/5 | 两条烟酸/乙醇胺偶联直接对应酰胺尾部，其他前排未解决联芳键 |
| T11含氟无环目标 | 0/5 | 0/5 | 仍主要是普通酯化/转酯或不相关骨架变化 |

T04第二轮的9351003原文把一个试剂写为TFA，计量却更像TEA；其酰胺构建方法仍有参考，但不能直接照抄试剂名称。这说明即使实际来源分数较高，仍需要化学内容核对。

以上结果没有表明化学排序已经整体改善：适配解决的是“被分析的实验必须真实合格且数据不串来源”，而非自动修复反应抽取、覆盖度评分、分层配额或方法迁移判断。组内最高分也不是化学质量最优的充分条件；目前明确只取一条，后续如需多来源择优，应单独设计预算与证据评估。

## 使用与复测

启动环境配置：

```text
RR_SOURCE_KIND=postgres
RR_POSTGRES_TABLE=reaction_v3
# RR_POSTGRES_DSN通过已有安全环境配置提供
```

新启动的CLI/API任务默认使用v3；已经运行的长驻进程需要重新加载代码。旧结果快照保持历史内容，不会被切表重新查询改写。没有对源数据库执行迁移、回填、更新或索引创建。

复测脚本已接通正式v3逻辑：

```bash
# 通过安全环境配置预先设置RR_BENCH_DSN，不在文件中填写密码。
RR_BENCH_TABLE=reaction_v3 RR_BENCH_OUTPUT=/tmp/rr-v3-adapted-repeat \
  implementation/.venv/bin/python reviews/live_benchmark_2026_10_31/benchmark.py --repeats 2
```

不同来源、实现哈希或预算的缓存不会混用。完整原文/资料包保存在本机 `.cache/live-benchmark-v3-adapted-2026-11-01/`，本目录仅归档判断、结构图、必要定位和计时，不提交密码及大段原文。

真实SDK额外冒烟通过：默认配置经spawn子进程建立v3来源，所有返回实验自身分数≥12，保存的完整资料包与返回对象一致，临时运行目录已清理。该额外冒烟不计入22次性能统计，记录见sdk_smoke.json。
