## 规则配置与运行约束复核（2026-10-30）

## 映射端点支持范围复核（2026-10-30）

确认反应分析与来源检索的材料校验不一致：来源适配器拒绝增强立体组，但 `analyze_reaction` 用普通规范 SMILES 校对声明材料与映射端点，会丢失增强立体组语义。增强立体组出现在映射侧或声明材料中时，可能与普通明确构型对应，并错误输出 `analyzed / single_mapping_inference`；映射侧的虚原子也没有阻止这一结论。

现在校对前检查映射两侧，不接受虚原子或增强立体组，返回未知及 `unsupported_mapped_endpoint_structure`。映射整侧仍允许多个真实组分；声明的每个材料实例则复用 `parse_material` 的具体结构校验，无法支持时保留 `invalid_declared_material_structure`。不支持的反应分析不输出已确认的键变化；同一记录中的有效产物仍参与检索并作为结构线索保留，已有来源产品观察不受此图分析状态替代。

新增 [端点表示回归](../tests/test_mapping_representation.py) 六项：映射反应物侧增强立体组、声明材料增强立体组、反应物侧虚原子、正常氧化对照，以及产物侧增强立体组/虚原子。前四项修复前 **3 项失败、1 项对照通过**；修复后六项均通过。其中四项同时检查完整检索包、贡献类别及排序证据字段。

完整本地检查 **340 项测试通过、无跳过**，含 17 项 PostgreSQL、6 项真实浏览器和 10 个 Node 场景；中文说明、Ruff、mypy、契约及 wheel 构建通过。固定样本 12 个目标、24 种任务重跑，目标自命中与屏蔽隔离正常。本轮仅统一现有不支持表示的校验边界，没有扩充化学规则、访问现库或增加 CI。

## 多行详情关联歧义复核（2026-10-30）

确认 `PostgresSource._fetch_details` 使用 `LIMIT 1` 获取详情，关联键匹配多行时会任取一条。直接 `reaction_id` 模式只检查字段存在，并不保证该列唯一；来源组合键的约束缺失或脏重复也有相同问题。即使未把详情升级为制备证据，任意附入的材料名称及温度文本仍会误导参考解释。

现在关联查询最多取两行：零条仍返回无详情，一条正常补全，多条记录 `ambiguous_reaction_details` 并抛出受控错误。详情保存点回滚后，会话可继续使用；检索编排沿用 `source_hydration_failed` 回退到轻量反应，保留有效结构参考并标记部分范围，不附入歧义名称或条件。不要求全量计数，不修改源表或约束。

新增两个 [真实 PostgreSQL 回归](../tests/test_postgres_integration.py)，分别模拟直接 ID 非唯一和组合键约束缺失后的重复详情。修复前两项均未拒绝歧义；修复后验证未缓存错误详情、事务仍可查询，以及完整搜索保留目标参考、缺失详情字段保持空值、来源问题准确记录。原有无详情/唯一详情回归继续通过。

完整本地检查 **344 项测试通过、无跳过**，含 19 项 PostgreSQL、6 项真实浏览器和 10 个 Node 场景；中文说明、静态检查、契约及 wheel 构建通过。固定样本 12 个目标、24 种任务重跑，目标自命中与屏蔽隔离正常。本轮没有访问现库或增加 CI。
