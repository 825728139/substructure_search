# 数据边界补充审查

本轮继续检查当前代码的输入校验、数据归属与文件发布，没有扩展化学规则。新增确认并修复四类问题。

| 问题 | 原实现与触发条件 | 修复 |
|---|---|---|
| 来源身份缺失导致错误去重 | 文献、段落或反应序号为 `None` 时，不同记录可得到同一个 `patent:None:None:None` 实验身份，导致实验统计少计；空记录 ID 也会转成共享字符串 | 完整定位才按实验归组；缺失定位退回来源记录身份。序号 0 仍合法；空、空白、布尔或缺失记录 ID 在导出行适配入口拒绝 |
| 空结果重排跳过排除结构校验 | 排除结构只在逐参考排序时解析，结果池为空时 `invalid(` 也能创建成功的派生任务 | 检索和重排共用实验上下文校验，在创建任务前校验排除结构，不依赖参考数量 |
| 文件内身份未与路径核对 | 把其他任务的合法状态/快照 JSON 放到当前路径时，读取会直接返回另一个任务的数据 | 状态读取核对 run_id；快照读取同时核对 run_id 与 snapshot_id，错配报告冲突。重启恢复也通过同一检查读取状态 |
| 失败导出留下残缺最终文件 | 直接向最终路径逐行写入，第二条记录序列化失败后第一行仍留在文件中，下一次同路径导出又拒绝覆盖 | 在同目录临时文件完成序列化并同步文件后，用硬链接原子创建最终名称；失败清理临时文件。并发发布不覆盖先完成者，原有文件始终保留 |
