# 三轮代码复审记录

本次在[上一轮整体审查](CODE_REVIEW.md)基础上，依次检查化学表示、反应分析与回放、数据约束与执行状态。每轮先构造反例，再修复并回归，分别用中文 Git 提交记录。

## 第 1 轮：精确支链的立体信息

确认两类问题：

- `fragment_key` 只复制键型，没有重建双键的立体参照原子，导致 E、Z 和未指定构型的支链具有同一签名。精确 R 查询因此接受了错误构型。
- 原分子采用显式氢表示时，直接丢掉氢邻居再复制手性原子，会丢失四面体手性，导致同一目标反而不能通过精确支链查询。

修复时重建双键参照，并将核心边界参照换成对应虚拟端口；普通氢先保留到局部图建立完成，再交给 RDKit 折叠。同位素氢继续保留。

验证见 [test_round1_chemistry.py](../tests/test_round1_chemistry.py)：修复前 7 个场景中 4 个失败；修复后全部通过。覆盖 E/Z/未指定构型、四面体反构型、显式氢、氘和原子重排。第 1 轮完整自检通过 99 项测试、中文说明检查、静态检查、契约检查及构建。

## 第 2 轮：反应解释与回放前提

确认并修复四类问题：

1. 映射不完整或整个环片段未被跟踪时，原代码仍可能报告 `ring_topology_retained`。现在只有可确认时才报告保留，无法确定的情况返回 `ring_topology_unknown`。
2. 宽泛核心查询允许额外边或任意键型时，来源新成键即使在目标中不存在或键型不同，也可能被列为目标成键。现在投影必须核对原始目标中的真实键与键型，原始来源变化仍保留。
3. 来源自回放失败不计入尝试预算，可能在剩余额度耗尽后继续调用。现在每次实际自回放开始前计数，并在各输入分配之间检查时间预算。
4. 空白步骤引用会被视为明确单步证据，进而允许替换回放。统一契约与回放入口均改为要求非空白引用。

验证见 [test_round2_reactions.py](../tests/test_round2_reactions.py)，包括环变化未知、宽泛查询错误成键投影、失败尝试额度及空白步骤引用。本轮 9 个场景全部通过；完整自检通过 108 项测试及静态、契约、构建检查。

## 第 3 轮：审核补丁、条件与服务边界

确认并修复五类问题：

1. 只填写实际输入引用的审核，也会用模型默认空值清除已有产品观察、步骤范围和引用。现在仅覆盖显式提供的字段；显式 `observations: []` 仍表示清空，审核哈希也区分这两种操作。
2. 来源温度下限大于上限时，可能错误通过实验能力比较；负时长还会获得优先排序。现在异常条件保留原值并附加原因，不参与正常条件数值比较。正常低温和零时长仍有效；重排旧缓存时补充解释但不改写原快照。
3. 初始化取得目录锁后，恢复旧状态失败可能让锁随异常对象一起滞留。现在失败立即释放锁，调用方保留异常也可再次初始化。
4. 无效的排除材料 SMILES 会被接纳后才让任务失败。现在在创建状态和调度之前校验，直接返回输入错误。
5. 重排旧资料时只有原检索代码哈希，无法确认本次排序由哪版代码产生。现在保留原哈希，另记录 `rerank_implementation_hash` 与 `reranked_at`。

验证见 [test_round3_boundaries.py](../tests/test_round3_boundaries.py)。修复前的边界反例中有 7 项失败、1 项正确通过，另一个重排版本记录反例也失败。修复后 11 个场景全部通过，包括旧特征缓存不被修改的正反例。本轮完整检查通过 119 项测试、中文说明、Ruff、mypy、契约漂移和 wheel 构建。
